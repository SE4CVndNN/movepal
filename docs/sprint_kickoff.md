# MovePal Sprint 1 kickoff package

## Kickoff date

Monday, 13 July 2026.

## Learning introduction

1. Waterfall: plan phases largely in sequence; change can be costly late.
2. Agile: deliver and learn incrementally, use feedback, and adapt.
3. Scrum: a lightweight framework using a Product Backlog, Sprint Goal, Sprint Backlog, roles, events, review, and retrospective.
4. GitHub mapping:
   - Product Backlog: all 63 issues
   - Sprint Backlog: MP-001 through MP-033
   - Work stages: Backlog, New, In Progress, In Review, QA, Blocked, Done
   - Increment: the tested MovePal release candidate/demo

## Sprint Goal

By 29 July 2026, Team B will deliver a documented Flask-based MovePal prototype with three movement activities, live-camera or fallback input, pretrained pose landmarks, rule-based friendly feedback, points/stars, session summary, tests, Windows/Linux CI, privacy/limitations content, and a reliable fallback demonstration. Team A will perform final-day external manual sanity QA against a frozen release candidate.

## Student workflow

1. Read the full issue and dependencies.
2. Confirm prerequisite outputs are merged.
3. Move the issue from New to In Progress.
4. Time-box learning/investigation and record findings.
5. Create the suggested branch.
6. Implement the smallest complete change and tests.
7. Open a draft PR early, link the issue, and include evidence.
8. Request the suggested independent reviewer.
9. Resolve comments and pass CI.
10. Squash merge and move the issue to Done only after the Definition of Done is satisfied.

## Scrum rituals

- Team B development stand-up: 10 minutes each workday.
- Team A QA synchronization: only as needed before/final QA day; the manual execution is on 29 July.
- Instructor checkpoints: Monday and Wednesday.
- One Sprint Rituals issue tracks dated checklists; meetings are not split into micro-issues.
